## ١. فحص `export.test.ts` الفاشل — **انصلح**

### العطل

```
FAIL packages/utils/tests/export.test.ts > exportToSvg > with default arguments
Error: Snapshot `exportToSvg > with default arguments 1` mismatched

- "boxSelectionMode": "contain",     ← الصورة المحفوظة
+ "boxSelectionMode": "overlap",     ← النتيجة الحالية
```

### شو يعني snapshot

بعض الفحوصات بتصوّر النتيجة الصح مرة وحدة وبتحفظ الصورة بملف `.snap`. كل تشغيل جاي بيقارن النتيجة الحالية بالصورة. لو اختلفوا، الفحص بيصير أحمر. فالفحص هون ما اكتشف خطأ بالكود — اكتشف إن الصورة المحفوظة صارت قديمة.

### السبب

بالكوميت `c901443` انتغيّر الإعداد الافتراضي لطريقة التحديد بالماوس:

| | القيمة | المعنى |
|---|---|---|
| قبل | `contain` | لازم مربع التحديد يحيط بالعنصر كامل |
| بعد | `overlap` | يكفي يلمس العنصر |

الموقع: `canvas/packages/excalidraw/appState.ts:164`

هذا التغيير غيّر نتيجة **١٤٩ إدخال snapshot موزّعين على ٧ ملفات**. كلهم انجدّدوا، إلا هذا.

### الجزء الغريب

الملف `packages/utils/tests/__snapshots__/export.test.ts.snap` **انجدّد فعلاً** بنفس الكوميت — انضافت له مفاتيح جديدة:

```

+ "currentItemEraserSize": 18,
+ "currentItemPolygonSides": 6,
+ "currentItemShape3DType": "cube",
+ "engineeringInstrument": null,
+ "paperMode": "dotted",
```

بس `boxSelectionMode` ما انلمس. يعني التجديد كان **جزئي** — ضاف المفاتيح الجديدة وما عدّل القديمة. على الأغلب لأن التجديد صار على مرحلتين بأوقات مختلفة.

### الإصلاح

```bash
yarn vitest run packages/utils/tests/export.test.ts -u
```

الناتج: سطر واحد.

```diff
- "boxSelectionMode": "contain",
+ "boxSelectionMode": "overlap",
```

## ٢. خطوط Assistant بترجع 404 — **انصلح**

### العطل

على صفحات الكانفاس، أربع طلبات بترجع 404:

```
/assets/Assistant-Regular.woff2    404
/assets/Assistant-Medium.woff2     404
/assets/Assistant-SemiBold.woff2   404
/assets/Assistant-Bold.woff2       404
```

### التشخيص الأول كان غلط

الفرضية الأولى كانت: «الملف موجود على القرص، Vite بس ما بينسخه.» هذا **مش صحيح**، وكان بيوصّل لحل غلط (نسخ الملفات يدوياً لـ `public/`).

### السبب الحقيقي

في بلَجن اسمه `woff2BrowserPlugin` بـ `canvas/scripts/woff2/woff2-vite-plugins.js`. أثناء بناء الإنتاج، بيستبدل محتوى `fonts.css` بنص جاهز، وبيحط لكل خط مصدرين:

```css
src: url(https://excalidraw.nyc3.cdn.digitaloceanspaces.com/oss/fonts/Assistant/Assistant-SemiBold.woff2)
       format("woff2"),
     url(./Assistant-SemiBold.woff2) format("woff2");   /* ← احتياطي */
```

المصدر الأول CDN تبع excalidraw، والتاني نسخة محلية احتياطية.

المشكلة بالمسار المحلي. `fonts.css` موجود بـ:

```
packages/excalidraw/fonts/fonts.css
```

فـ `./Assistant-SemiBold.woff2` بيتحوّل لـ:

```
packages/excalidraw/fonts/Assistant-SemiBold.woff2      ← غير موجود
```

بينما الملف الحقيقي بمجلد فرعي:

```
packages/excalidraw/fonts/Assistant/Assistant-SemiBold.woff2   ← هون
```

Vite ما بيقدر يلاقي الملف، فما بيعالج الرابط ولا بينسخ الملف — بيسيب النص زي ما هو. النتيجة رابط ميت بالإنتاج.

### الدليل القاطع

قبل الإصلاح، `dist/fonts/` كان فيه **٨ عائلات خطوط** وما فيه Assistant:

```
CascadiaCode  ComicShanns  Excalifont  LiberationSans
Lilita        Nunito       Virgil      Xiaolai
```

كل العائلات التانية مساراتها صح فانبعثت. Assistant لحالها مسارها مكسور فانتخطّت.

### ليش ما ظهرت عند صاحب المشروع

المصدر الأول (الـCDN) بيشتغل عنده. المتصفح ما بيطلب الاحتياطي إلا لما الأول يفشل. فالـ404 ما بتبيّن إلا لما الاتصال بالـCDN ينقطع أو ينحجب.

### الإصلاح

بـ `canvas/scripts/woff2/woff2-vite-plugins.js` — أربع أسطر:

```diff
- url(./Assistant-Regular.woff2) format("woff2");
+ url(./Assistant/Assistant-Regular.woff2) format("woff2");

- url(./Assistant-Medium.woff2) format("woff2");
+ url(./Assistant/Assistant-Medium.woff2) format("woff2");

- url(./Assistant-SemiBold.woff2) format("woff2");
+ url(./Assistant/Assistant-SemiBold.woff2) format("woff2");

- url(./Assistant-Bold.woff2) format("woff2");
+ url(./Assistant/Assistant-Bold.woff2) format("woff2");
```

### التحقق بعد إعادة البناء

```
dist/fonts/Assistant/  ← صار موجود
  Assistant-Regular.woff2    20232 بايت   md5 مطابق للمصدر
  Assistant-Medium.woff2     20320 بايت   md5 مطابق للمصدر
  Assistant-SemiBold.woff2   20212 بايت   md5 مطابق للمصدر
  Assistant-Bold.woff2       20380 بايت   md5 مطابق للمصدر
```

والرابط بالـCSS المبني صار:

```css
url(../fonts/Assistant/Assistant-SemiBold.woff2)
```

من داخل `dist/assets/` هذا بيوصل صح لـ `dist/fonts/Assistant/`. الخط صار يشتغل حتى بدون إنترنت.

**هذا خطأ upstream — موجود بـ excalidraw الأصلي، مش من شغل صاحبك.**

## ٣. `dist/` ما بينتنضّف أبداً — انصلح

### الحجم

```
dist كامل        ٣٥٢ ميجا
منها حيّة         ٣٦ ميجا   (١١٣ ملف، موصولة من index.html)
منها ميتة        ٣٠٠ ميجا   (٢٦٧ ملف)
مستودع .git      ١.١ جيجا
```

تفصيل الميت:

| النوع | العدد | الحجم |
|---|---|---|
| `.js` | ١٢٤ | ٥١.١ م |
| `.js.map` | ١٢٤ | ٢٤٣.٩ م |
| `.css` | ١٧ | ٣.٦ م |

البندل الرئيسي لحاله متكرر **٢٠ مرة**:

```
٢٠٢٦-٠٨-٠٩   index-BW3C54dc.js   ← الوحيد الحيّ
٢٠٢٦-٠٨-٠٧   index-CKAaAFhm.js   ميت
٢٠٢٦-٠٨-٠٧   index-tDH9C7_L.js   ميت
٢٠٢٦-٠٨-٠٧   index-DcSWFmqn.js   ميت
... و١٥ نسخة تانية من ٥ و٧ آب
```

و`index.html` بيحمّل نسختين بس:

```
assets/index-BW3C54dc.js
assets/index-Ctha6KR7.css
```

### السبب

Vite بيمسح مجلد الإخراج قبل كل بناء، **بشرط** إنه يكون جوّا مجلد المشروع. هون:

```
مجلد المشروع (root)   excalidraw-app/
مجلد الإخراج (outDir)  ../dist        ← برّا، فوق بمستوى
```

لما الإخراج يكون برّا الجذر، Vite بيرفض يمسحه لحاله — حماية عشان ما يمسح ملفات مهمة بالغلط. بيطلّع تحذير وبيتخطّى المسح. وبيرجع يمسح بس إذا انكتب `emptyOutDir: true` صراحةً.

فحصنا `canvas/excalidraw-app/vite.config.mts`: **الإعداد مش موجود أبداً**.

النتيجة: كل بناء بيكتب ملفات بأسماء جديدة (الاسم فيه بصمة المحتوى، فبيتغيّر مع أي تعديل) **جنب** القديمة مش مكانها. ولا مرة انحذف إشي.

### الإصلاح — انصلح

بـ `canvas/excalidraw-app/vite.config.mts` جنب `outDir: "../dist"`:

```diff
  outDir: "../dist",
+ emptyOutDir: true,
```

بعدها: `rm -rf dist && yarn build` — إعادة بناء نظيفة من الصفر.

**النتيجة بعد التنفيذ:**

```
dist كامل     ٣٥٢ م  →  ٥٣ م
نسخ index.js  ٢٠      →  ١  (نسخة بناء اليوم بس)
```

`emptyOutDir: true` بيمنع تكرار المشكلة للأبد — كل بناء جاي بينضف المجلد قبل ما يكتب فيه.

**ملاحظة:** `canvas/.gitignore` فيه `dist` وبعدها `!/dist/` — يعني رفع `dist` **مقصود** (على الأغلب للنشر). ما وقفنا رفعه، بس نظّفناه.

## ٨. `/sitemap.xml` مرجوع وغير موجود — انصلح

`dist/index.html` فيه:

```html
<link rel="sitemap" type="application/xml" title="Sitemap" href="/sitemap.xml">
```

والملف مش موجود لا بـ `dist/` ولا بـ `public/`. يعني 404 لأي زاحف (crawler) بيتبع الرابط.

### السبب الحقيقي

المشروع فيه أصلاً بلَجن مخصص لتوليد الـsitemap (`vite-plugin-sitemap`) بـ `canvas/excalidraw-app/vite.config.mts`:

```diff
  Sitemap({
    hostname: "https://excalidraw.com",
-   outDir: "build",
+   outDir: "../dist",
    changefreq: "monthly",
    generateRobotsTxt: false,
  }),
```

نفس نمط مشكلة الخط بالضبط: مسار المخرجات الحقيقي `../dist`، بس البلَجن كان معطّى `"build"` — مجلد ما بينعمل. فالملف كان يتولّد بمكان ميت ومحدا بيشوفه.

**التحقق بعد الإصلاح:** `dist/sitemap.xml` صار موجود فعلياً (٤٧٨ بايت، صيغة XML صحيحة).

**متبقّي:** محتوى الـsitemap لسا فيه `hostname: "https://excalidraw.com"` — نطاق مش نطاقك. هذا وباقي مراجع excalidraw.com (رقم ٩) بحاجة نطاقك الحقيقي، تركناهم لحد ما يتحدد.

## ٩. `robots.txt` — مشكلة أرشفة — انصلح جزئياً

`canvas/public/robots.txt`:

```
User-agent: *
Allow: /$
Allow: /
Disallow: /

Sitemap: https://excalidraw.com/sitemap.xml
```

مشكلتين:

1. **`Sitemap:` بيأشّر على `excalidraw.com`** — مش على موقعك. متروك من upstream.
2. **`Disallow: /`** موجود مع `Allow: /` — قواعد متضاربة. سلوك محركات البحث هون مش مضمون وبيختلف من محرك لمحرك.

### الإصلاح — انصلح جزئياً

شلنا `Disallow: /` المتضارب وسطر `Sitemap:` الغلط. صار الملف:

```
User-agent: *
Allow: /$
Allow: /
```

قاعدة وحدة واضحة، بدون تضارب.

**متبقّي — بحاجة قرارك:** `hostname: "https://excalidraw.com"` بإعداد الـsitemap (رقم ٨)، و`<link rel="canonical" href="https://excalidraw.com">` بـ`excalidraw-app/index.html`، وسطر تحويل مشروط بكوكي لـ`app.excalidraw.com`. الثلاثة متبقّيات من الأصل، ومحدا بيفعّلهم فعلياً بحالتك الحالية (الكوكي المطلوب للتحويل ما بينتحط إلا من excalidraw.com نفسها). مش أخطاء بتكسر شي **الآن**، بس لو نشرت الموقع للعامة، لازم تتحدّث بنطاقك الحقيقي.

## ١٠. `math-lab` — فُحص بالكامل، نظيف

المشروع فيه جزئين: `canvas/` (تطبيق excalidraw مبني بـVite) و`math-lab/` (موقع ثابت HTML/JS بدون بناء). الفحص الأولي غطّى `canvas/` بس — فانعمل فحص منفصل لـ`math-lab`.

### الطريقة

انفحص **٢٦٣ ملف html/css** بكامل المشروع. لكل ملف، انستخرجت كل الروابط المحلية (`url(...)`, `href`, `src`) وانتأكد إن الملف المقصود موجود فعلاً على القرص.

### النتيجة: لا يوجد عطل

الشي الوحيد اللي طلع كان خطوط KaTeX، وطلع **إنذار كاذب**:

`math-lab/assets/vendor/katex.min.css` بيرجع لـ**٦٠ ملف خط** = ٢٠ خط × ٣ صيغ:

| الصيغة | موجودة؟ | بيطلبها المتصفح؟ |
|---|---|---|
| `.woff2` | ✓ الـ٢٠ كلهم | نعم — هذه اللي بتنستعمل |
| `.woff` | ✗ | لأ — بديل للمتصفحات العتيقة |
| `.ttf` | ✗ | لأ — بديل أقدم |

KaTeX بيسرد الصيغ بترتيب أولوية. كل المتصفحات الحديثة بتدعم `woff2`، فبتاخد الأولى وبتوقف. الـ`.woff` و`.ttf` عمرهم ما بينطلبوا، فما بتصير 404.

**لاحظ الفرق عن مشكلة رقم ٢:** نفس فكرة «مصدر أساسي + بديل»، بس هون **الأساسي شغّال** فالبديل ما بينطلب أصلاً. بمشكلة Assistant الأساسي (الـCDN) كان بيفشل، فالمتصفح كان بينزل عالبديل — والبديل كان مكسور.

## المتبقي — قرارك

كل شي بالجدول أعلاه انصلح إلا نقطة وحدة، وهي مش خطأ بيكسر شي — نطاق:

## ملاحظة عامة

كل الملاحظات الأصلية الثلاث كانت من نفس النوع: أشياء ما بتظهر إلا لما تبني المشروع بنفسك وتشغّله فعلياً.

- الخط: مصدره الأساسي (CDN excalidraw) شغّال، فالمسار المحلي المكسور ما كان يبيّن إلا لما الاتصال بالـCDN ينقطع.
- الـsnapshot: التجديد الشامل بعد تغيير `boxSelectionMode` غطّى ١٤٩ إدخال بـ٧ ملفات، وانتخطّى إدخال واحد بالغلط.
- الـ`dist`: **تصحيح** — ما نفخ من بناءات متكررة أثناء الشغل الحالي. تتبعنا كل نسخة بتاريخ الكوميت اللي جابها: ١٢ نسخة من الكوميت الأول (٥ آب)، ٧ من إصدار ٩ آب، ونسخة وحدة من بناء اليوم. يعني الملفات الميتة كانت **محفوظة جوّا الكوميتات من الأساس** — كل بناء أثناء التطوير بيتكدّس بـ`dist` بصمت (بسبب `outDir` برّا مجلد المشروع)، وبعدين بينترفع كامل مع الكوميت التالي بدون تمييز حي من ميت.
