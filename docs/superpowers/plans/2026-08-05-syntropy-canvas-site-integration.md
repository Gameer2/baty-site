# Syntropy Canvas Site Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Syntropy Canvas reachable from the site like every other page — build it to a committed static bundle, link to it from the General Lab hub, and fix the library-panel-induced toolbar regression — with no vendored Excalidraw source patched.

**Architecture:** Four independent changes. (1) `vite.config.mts` gets `base: "./"` (relative asset paths) and `outDir: "../dist"` (build to `canvas/dist/`). (2) `App.tsx` adds Excalidraw's supported `UIOptions.getFormFactor` override that adds the 240px library panel back before calling Excalidraw's own `getFormFactor`, so the desktop floating-pill toolbar renders on normal laptop windows. (3) `yarn build` produces `canvas/dist/`, which is un-ignored (one `.gitignore` line) and committed. (4) `math-lab/index.html` gets a new `#workspace` section after `#engines` with a single full-width `.card.engine-card.crosshair-host` linking to `canvas/dist/index.html` — full-width, not in the 7-engine grid, to read as "the workspace that uses the engines," not an 8th engine.

**Tech Stack:** Vite (build config), React/TypeScript (Excalidraw host app), static HTML/CSS (math-lab hub), vitest (regression).

## Global Constraints

- **No vendored Excalidraw source edits.** The toolbar fix uses `<Excalidraw>`'s public `UIOptions.getFormFactor` extension point in our own `App.tsx`; do not edit `packages/excalidraw/` or `packages/common/`.
- **No CI/deploy pipeline.** The site is opened as plain static files; `canvas/dist/` is generated output committed once via `yarn build` + `git add`. Re-building on source change is a manual step (accepted limitation per spec §2).
- **`base: "./"`** — relative asset paths only; no absolute-root assumptions (matches the rest of the site).
- **Not an 8th engine.** The workspace card is a new section outside the `#engines` `.engine-grid`; no `engine-index` badge; neutral `--electric-teal:#e7e7e7` accent.
- **`LIBRARY_PANEL_WIDTH` must match the panel's actual width.** `LibraryPanel.scss` sets `.LibraryPanel { width: 240px }`; the constant in `App.tsx` is `240`.
- **Lint gate:** `yarn test:code` (`eslint --max-warnings=0`) and `yarn test:typecheck` must stay green. Run `npx eslint --fix` on touched TS/TSX before committing (do not pass `.scss`/`.mts`/`.html` to eslint — no parser for them here).

### Task 2: Toolbar/form-factor fix in `App.tsx`

**Files:**
- Modify: `canvas/excalidraw-app/App.tsx` (the `@excalidraw/common` named import block ending at line 33; a module-level const; the `<Excalidraw>` `UIOptions` prop around lines 1014–1045).

**Interfaces:**
- Consumes: `getFormFactor` exported from `@excalidraw/common` (re-exported via `packages/common/src/index.ts` → `./editorInterface`); signature `(editorWidth: number, editorHeight: number) => EditorInterface["formFactor"]`. The `UIOptions.getFormFactor?` host override (defined at `packages/excalidraw/types.ts:1022`) has the same signature.
- Produces: a `<Excalidraw>` whose form-factor decision is made against the user's real window width (`editorWidth + 240`) instead of the penalized Excalidraw-container width, so the desktop floating-pill toolbar renders on ordinary laptop windows instead of collapsing to the tablet/mobile toolbar.

- [ ] **Step 1: Add `getFormFactor` to the `@excalidraw/common` named import**

In the big named-import block that ends with `} from "@excalidraw/common";` (line 33), add `getFormFactor,` to the list (e.g. right after `isDevEnv,`):

```ts

  getFormFactor,
} from "@excalidraw/common";
```

- [ ] **Step 2: Add the `LIBRARY_PANEL_WIDTH` module const**

Near the other module-level consts (e.g. just before `const shareableLinkConfirmDialog = {` around line 218), add:

```ts
// The library panel renders as a 240px flex sibling of <Excalidraw>, so
// Excalidraw's own container is 240px narrower than the real window and it
// picks the tablet/mobile form factor on ordinary laptops. We add this back
// before Excalidraw's own getFormFactor so the breakpoint matches the window.
// Must match .LibraryPanel { width } in LibraryPanel.scss.
const LIBRARY_PANEL_WIDTH = 240;
```

- [ ] **Step 3: Add the `getFormFactor` override to `UIOptions`**

In the `<Excalidraw>` `UIOptions={{ canvasActions: { ... } }}` prop (lines 1014–1045), add `getFormFactor` as a sibling key of `canvasActions` inside the `UIOptions` object:

```tsx
          UIOptions={{
            canvasActions: {
              // ...existing canvasActions unchanged...
            },
            getFormFactor: (editorWidth, editorHeight) =>
              getFormFactor(editorWidth + LIBRARY_PANEL_WIDTH, editorHeight),
          }}
```

### Task 3: Build, un-ignore, and commit `canvas/dist/`

**Files:**
- Modify: `canvas/.gitignore` (add a negation so the top-level `dist/` is tracked).
- Create (generated): `canvas/dist/` (the static build).

- [ ] **Step 1: Un-ignore the top-level `canvas/dist/`**

`canvas/.gitignore` has a bare `dist` rule that ignores `dist` at any depth. Append a negation anchored to the canvas root so only the top-level `dist/` is tracked (nested `dist`s stay ignored). Add immediately after the `dist` line:

```gitignore
dist
!/dist/
```

(`dist` ignores all `dist` dirs; `!/dist/` re-includes only the top-level one — leading slash anchors to `canvas/`. Once the dir is un-ignored, git descends and `dist/index.html`, `dist/assets/*` are tracked since no rule ignores them individually.)

[...] : []` style or comment it) and re-run; record what you did in the commit message. Prefer leaving it enabled if the build is green.
